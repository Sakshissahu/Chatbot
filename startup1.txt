================================================================
  IB GROUP CHATBOT — FULL STARTUP GUIDE (from a cold laptop)
================================================================
  Follow these in ORDER. Each part must be running before the next.
  Keep every terminal/window OPEN — closing one stops that service.
  Laptop must stay PLUGGED IN and AWAKE while people use the demo.
================================================================


----------------------------------------------------------------
 THE 4 THINGS THAT MUST RUN (in this order)
----------------------------------------------------------------
   1. RAGFlow        (Docker)            — the AI engine + bots
   2. App Postgres   (Docker)            — logging + chat history
   3. Backend        (Node, terminal)    — the middle layer
   4. Tunnel + Deploy (start-demo.ps1)   — makes it public

   (The frontend is on Vercel already — you don't start it locally.)


================================================================

================================================================

  icon says it's running. Nothing below works until Docker is up.

================================================================

     docker compose -f docker-compose.yml up -d

 STEP 2 — Start the app's Postgres (logging/history DB)
================================================================

     cd C:\Users\prajjwal.kushwaha\Documents\CODE\BDchatbot\ragflow\myui-backend
     docker compose up -d

================================================================

================================================================

    cd C:\Users\prajjwal.kushwaha\Documents\CODE\BDchatbot\ragflow\myui-backend
     npm run dev

    cd C:\Users\prajjwal.kushwaha\Documents\CODE\BDchatbot\ragflow\myui

================================================================

================================================================
 SHUTTING DOWN (end of day)
================================================================
  - Close the tunnel terminal (or run: .\stop-demo.ps1 from ragflow)
  - Stop the backend: Ctrl+C in its terminal
  - Stop Docker services (keeps all data):
       cd C:\Users\prajjwal.kushwaha\Documents\CODE\BDchatbot\ragflow\docker
       docker compose -f docker-compose.yml stop
       cd ..\myui-backend
       docker compose stop

  ⚠️ NEVER run "docker compose down -v" — the -v DELETES all data
     (docs, chats, logins). Always use "stop".

================================================================
 MANAGING BOTS  (admin work — done in RAGFlow at http://localhost)
================================================================

  KEY IDEA:
   - A bot's SETTINGS (model, prompt, temperature, which datasets) live
     in RAGFlow's admin UI, per bot. Change anytime — NO code needed.
   - The PUBLIC APP just routes a role -> a bot's ID. Adding/removing a
     bot from the public app needs a small frontend change (role + ID).

  Current bots (their IDs, for reference):
     Farmer   ("IB-assist")          = 66824bb2675f11f1bb5ca9173f52da2e  -> "farmer docs"
     Employee ("Employee Assistant") = 2150f758676111f1bb5ca9173f52da2e  -> "HR policy"


  ----------------------------------------------------------------
   A) CHANGE AN EXISTING BOT'S SETTINGS  (e.g. switch model)
  ----------------------------------------------------------------
   100% in RAGFlow admin UI — no code, no redeploy.

   1. http://localhost  -> log in (admin@ibgroup.co.in)
   2. Click "Chat" in the top nav
   3. Open the bot (e.g. IB-assist) -> its settings
   4. Change what you want:
        - Model Setting tab  -> pick a different model (e.g.
          llama-3.1-8b-instant for lighter/cheaper), temperature, etc.
        - Prompt Engine tab  -> system prompt, similarity threshold,
          Top N, empty-response (the "refuse" message), etc.
        - Assistant Setting tab -> datasets linked, greeting, citations
   5. Save.  The public app uses the new settings immediately —
      nothing to redeploy (it just talks to the same bot ID).

   NOTE: saving Model Setting may flash the "model_type" error once —
   the MySQL trigger strips it; just start a fresh chat. If it sticks,
   run:  docker restart docker-ragflow-cpu-1  (wait 1 min).


  ----------------------------------------------------------------
   B) ADD A BRAND-NEW BOT  (e.g. a 3rd role like "Manager")
  ----------------------------------------------------------------
   Two parts: make the bot in RAGFlow (admin), then add it to the
   public app (small frontend change via Claude Code).

   PART 1 — In RAGFlow admin (http://localhost):
     1. Dataset tab -> Create dataset -> name it (e.g. "Manager docs")
          * IMPORTANT: set its embedding model to the SAME one the
            others use: BAAI/bge-small-en-v1.5
     2. Upload that bot's documents -> select them -> Parse -> wait green
     3. Chat tab -> Create Assistant -> name it (e.g. "Manager Assistant")
          * Datasets: select ONLY that new dataset (keeps it isolated —
            it won't answer other roles' questions)
          * Empty response: e.g. "I can only help with manager topics."
          * Model: same Groq model (or whatever you want)
          * System prompt: its persona (can include {user_name})
     4. Save and test it in the UI.
     5. Get its BOT ID (dialog_id) — from the URL when the assistant is
        open, or ask Claude Code to read it from the DB.

   PART 2 — Add it to the public app (frontend — Claude Code task):
     Give Claude Code a prompt like:
       "In ragflow/myui, add a new role 'Manager' to the role-select
        screen, mapped to bot/dialog_id <THE_NEW_ID>. Follow the exact
        pattern already used for Farmer and Employee (role -> bot_id
        routing in the backend + a role card in the frontend). Keep the
        existing design/identity. Don't touch the other bots."
     Then redeploy:  .\start-demo.ps1

   Result: new role appears on the login/role screen, routes to the new
   bot, stays isolated to its own dataset.


================================================================
 IF SOMETHING'S BROKEN
================================================================
  - Link loads but chat fails / "Request failed" →
      backend (Step 3) or tunnel (Step 4) isn't running. Restart them.
  - 502 / "network anomaly" at http://localhost →
      RAGFlow still booting; wait 1–2 min, refresh.
  - model_type error in a chat →
      start a fresh chat (the DB trigger handles it). If it persists,
      restart: docker restart docker-ragflow-cpu-1 (wait 1 min).
  - Tunnel won't start →
      re-run .\start-demo.ps1; check backend is up on :8088 first.
  - Check everything running:  docker ps
