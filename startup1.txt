================================================================
  IB GROUP CHATBOT — LOCAL STARTUP GUIDE (from a cold laptop)
================================================================
  Follow these in ORDER. Each part must be running before the next.
  Keep every terminal/window OPEN — closing one stops that service.
================================================================


----------------------------------------------------------------
 THE 3 THINGS THAT MUST RUN (in this order)
----------------------------------------------------------------
   1. Docker stack   (Docker)            — RAGFlow (AI engine + bots)
                                           AND the app Postgres, all in ONE stack
   2. Backend        (Node, terminal)    — the middle layer (BFF)
   3. Frontend       (Node, terminal)    — the web UI

  (The app's Postgres is now part of the Docker stack — no separate step.)


================================================================
 STEP 0 — Make sure Docker Desktop is running
================================================================
  Open Docker Desktop from the Start menu. Wait until the whale
  icon says it's running. Nothing below works until Docker is up.

================================================================
 STEP 1 — Start the whole Docker stack (ONE command)
================================================================

     cd docker
     docker compose up -d

  This starts EVERYTHING in one project named "ib_chatbot":
     ib_chatbot-ragflow-cpu-1   (the AI engine, on http://localhost:7072)
     ib_chatbot-mysql-1, -es01-1, -minio-1, -redis-1, -tei-cpu-1
     ibchat_postgres            (the app's logging/history DB, port 5442)

  Wait 1–2 minutes for RAGFlow to fully boot (http://localhost:7072
  should load the login page).

================================================================
 STEP 2 — Start the Backend (the middle layer / BFF)
================================================================

     cd myui-backend
     npm run dev          (keep open — http://localhost:7071)

================================================================
 STEP 3 — Start the Frontend (the web UI)
================================================================

     cd myui
     npm run dev          (keep open — http://localhost:5173)

  Open http://localhost:5173 in the browser to use the app.


================================================================
 STEP 4 — TEST
================================================================
    1. Open  http://localhost:5173
    2. Log in (any username; password is the demo password from
       myui-backend/.env -> DEMO_PASSWORD)
    3. Ask the Farmer bot: "What biosecurity measures for poultry sheds?"
       → should stream an answer with citations


================================================================
 SHUTTING DOWN (end of day)
================================================================
  - Stop the frontend: Ctrl+C in its terminal
  - Stop the backend:  Ctrl+C in its terminal
  - Stop the Docker stack (keeps all data):
       cd docker
       docker compose stop

  !! NEVER run "docker compose down -v" — the -v DELETES all data
     (docs, chats, logins). Always use "stop".


================================================================
 MANAGING BOTS  (admin work — done in RAGFlow at http://localhost:7072)
================================================================

  KEY IDEA:
   - A bot's SETTINGS (model, prompt, temperature, which datasets) live
     in RAGFlow's admin UI, per bot. Change anytime — NO code needed.
   - The public app just routes a role -> a bot's ID.

  Current bot in use (Farmer only):
     Farmer ("IB-assist") = 66824bb2675f11f1bb5ca9173f52da2e  -> "farmer docs"


  ----------------------------------------------------------------
   CHANGE THE BOT'S SETTINGS  (e.g. switch model)
  ----------------------------------------------------------------
   100% in RAGFlow admin UI — no code, no redeploy.

   1. http://localhost:7072  -> log in (admin@ibgroup.co.in)
   2. Click "Chat" in the top nav
   3. Open the bot (IB-assist) -> its settings
   4. Change what you want:
        - Model Setting tab  -> pick a different model, temperature, etc.
        - Prompt Engine tab  -> system prompt, similarity threshold,
          Top N, empty-response (the "refuse" message), etc.
        - Assistant Setting tab -> datasets linked, greeting, citations
   5. Save.  The public app uses the new settings immediately.

   NOTE: saving Model Setting may flash the "model_type" error once —
   the MySQL trigger strips it; just start a fresh chat. If it sticks,
   run:  docker restart ib_chatbot-ragflow-cpu-1  (wait 1 min).


================================================================
 IF SOMETHING'S BROKEN
================================================================
  - App loads but chat fails / "Request failed" ->
      backend (Step 2) isn't running. Restart it.
  - 502 / "network anomaly" at http://localhost:7072 ->
      RAGFlow still booting; wait 1–2 min, refresh.
  - model_type error in a chat ->
      start a fresh chat (the DB trigger handles it). If it persists,
      restart: docker restart ib_chatbot-ragflow-cpu-1 (wait 1 min).
  - Check everything running:  docker ps
================================================================
